================================================================================
EasyToolHub — PDF capabilities with Angular frontend + Java backend
DETAILED IMPLEMENTATION GUIDE (libraries, APIs, architecture)
================================================================================
Purpose: Full inventory of user-facing PDF features, plus concrete Java libraries,
Maven dependencies, system packages, Angular integration, and API shapes.

DECISION (locked):
  Stack = Angular frontend (existing EasyToolHub / Nx) + Java backend (Spring Boot).
  Do NOT rewrite PDF UI in React. Frontend stays Angular; heavy PDF ops move to Java.
  Hybrid model: light tools stay client-side; server-required tools call Java API.

TEAM MODEL (locked):
  Solo developer NOW → optimize for simplicity and ship speed.
  Design BOUNDARIES so the same layout scales later (replicas, job queue,
  optional service split, optional polyrepo) WITHOUT a rewrite.
  Do NOT adopt micro-frontends / Kubernetes / many Java services on day one.

Guideline:
  - Keep light tools in the browser (privacy, speed).
  - Use Java for encryption, real compress, HTML/Office convert, OCR, redact,
    digital sign, repair, PDF/A, and heavy batch jobs.
  - One monorepo, two deployables (Angular static + pdf-api container).
  - Folder roles: apps/ + libs/ (UI) · services/ (Java) · contracts/ (OpenAPI)
    · infra/ (compose) · docs/pdf/ (planning).
  - OpenAPI in contracts/pdf is the contract between UI and backend.
  - Feature-flag each tool’s backend path; migrate vertically (one tool at a time).

0.5 Scalability stages (grow without rewrite)
--------------------------------------------------------------------------------

  STAGE 0 — Solo now (IMPLEMENT THIS FIRST)
    CDN (Angular SSG) → 1× services/tool-api container
    Folders as in 0.1
    Sync request/response for small jobs
    Temp files deleted in finally + TTL cleaner
    Rate limit by IP
    Tools: encrypt/decrypt first, then compress, then HTML→PDF

  STAGE 1 — Traffic / long jobs (still one Java service)
    Add Redis in infra/compose
    Async endpoints for OCR/compress large files
    Scale services/tool-api to 2+ replicas
    Trigger when: jobs >30s, OOM, or single instance CPU pegged

  STAGE 2 — Domain split (only if needed)
    services/tool-api           page ops, encrypt, compress, watermark
    services/pdf-convert-api   Office/HTML/URL → PDF
    services/pdf-ocr-api       OCR only
    contracts/pdf/ stays the public facade contract Angular calls
    Trigger when: fat image, OCR starves encrypt, or deps conflict

  STAGE 3 — Org scale (multiple people / products)
    Optional polyrepo:
      easytoolhub-web          ← apps/ + libs/
      easytoolhub-tool-api      ← services/tool-api
      easytoolhub-contracts    ← contracts/
    Optional MFE only if a second web app/team needs PDF UI


--------------------------------------------------------------------------------
0.6 Decision trees (use every time you add a feature)
--------------------------------------------------------------------------------

  New PDF feature?
    ├─ Browser can do it well (small files)? → libs/pdf-tools (client services)
    └─ Needs encrypt / OCR / Office / real compress / sign / PDF/A?
          → contracts/pdf/openapi.yaml FIRST
          → then services/tool-api (same service)
                └─ Starving others or huge isolated deps?
                      → new services/<name>-api (Stage 2)

  Need micro-frontend?
    └─ Only if second app/team needs PDF UI independently
          → otherwise keep libs/pdf-tools lazy module

--------------------------------------------------------------------------------
0.8 Solo operating rules
--------------------------------------------------------------------------------

  1. Vertical slices: one tool end-to-end (flag → contract → API → Docker)
  2. Contract-first: update contracts/pdf/openapi.yaml BEFORE controller code
  3. Feature flags per tool in pdf-backend.config.ts
  4. No permanent PDF storage by default (tmp + delete)
  5. Honest UI for limits (max MB, max pages, etc.)
  6. Prefer qpdf/gs CLIs for encrypt/compress reliability when unsure
  7. Avoid iText/Aspose unless you buy a license
  8. Postpone Redis/MFE/K8s until a Stage trigger is real
  9. Never put OpenAPI only inside services/ — always mirror/source from contracts/
  10. Don’t create backend/ or api/ at repo root — use services/

--------------------------------------------------------------------------------
A. CORE EDIT / PAGE OPS
--------------------------------------------------------------------------------

Features:
  Merge, split, extract, delete, reorder, rotate, duplicate,
  insert blank, crop, page-size normalize

Primary library:
  Apache PDFBox 3
    classes: Loader, PDDocument, PDFMergerUtility, PDPage, PDPageTree,
             PDRectangle, Matrix (rotation), LayerUtility (optional)

Implementation notes:
  Merge:
    PDFMergerUtility.addSource(...) + mergeDocuments(MemoryUsageSetting)
    Or open each PDDocument and import pages with PDFCloneUtility patterns
  Split / extract / delete / reorder:
    Build new PDDocument; add pages by index from source
  Rotate:
    page.setRotation((page.getRotation() + degrees) % 360)
  Crop:
    page.setCropBox(new PDRectangle(x, y, w, h))
  Insert blank:
    new PDPage(PDRectangle.A4) inserted into PDPageTree
  Large files:
    MemoryUsageSetting.setupTempFileOnly() to avoid OOM

System assist (optional):
  qpdf --empty --pages f1.pdf f2.pdf -- out.pdf   (fast merge alternative)

Angular:
  Existing merge/split/workbench UIs; add "Server process" toggle for large/encrypted


--------------------------------------------------------------------------------
B. SECURITY & ACCESS
--------------------------------------------------------------------------------

Features:
  Encrypt, decrypt, permissions, cert encrypt, digital sign, verify, redact

Libraries:
  PRIMARY encrypt/decrypt/permissions:
    qpdf CLI (most reliable OSS) wrapped by Java ProcessBuilder
      qpdf --encrypt user-pass owner-pass 256 --print=none --modify=none -- in.pdf out.pdf
      qpdf --password=PASS --decrypt in.pdf out.pdf
  OR OpenPDF StandardEncryption / PDFBox StandardProtectionPolicy
    org.apache.pdfbox.pdmodel.encryption.AccessPermission
    org.apache.pdfbox.pdmodel.encryption.StandardProtectionPolicy
    org.apache.pdfbox.pdmodel.encryption.StandardDecryptionMaterial
  Digital signatures:
    PDFBox PDSignature + SignatureInterface
    BouncyCastle (bcprov, bcpkix) for PKCS#12 keystore / CMS
  Redaction (true remove):
    Hard in pure PDFBox (text position + content stream rewrite)
    Options:
      a) Commercial: iText pdfSweep / Apryse Redaction
      b) OSS approximate: render page → image → black boxes → image-only PDF
         (loses text; honest UI label "image redaction")
      c) PDFBox content-stream parsing + remove operators (complex)

Maven:
  pdfbox + bouncycastle (+ openpdf optional)
System:
  qpdf (strongly recommended for password tools)

Angular map:
  /pdf-tools/password-protect-pdf  → MUST call Java (current client throws)


Implementation sketch (PDFBox encrypt):
  AccessPermission ap = new AccessPermission();
  ap.setCanPrint(false);
  ap.setCanModify(false);
  StandardProtectionPolicy spp =
      new StandardProtectionPolicy(ownerPass, userPass, ap);
  spp.setEncryptionKeyLength(256);
  doc.protect(spp);
  doc.save(out);

Prefer qpdf in production for fewer edge-case failures.


--------------------------------------------------------------------------------
C. COMPRESS & OPTIMIZE
--------------------------------------------------------------------------------

Features:
  Compress, quality presets, linearize, remove unused, downsample, grayscale

Libraries / tools:
  Ghostscript CLI (best OSS compress):
    gs -sDEVICE=pdfwrite -dCompatibilityLevel=1.4
       -dPDFSETTINGS=/ebook|/screen|/printer
       -dNOPAUSE -dQUIET -dBATCH
       -sOutputFile=out.pdf in.pdf
  qpdf --linearize in.pdf out.pdf
  PDFBox custom:
    Iterate PDResources → PDImageXObject
    Resample with Thumbnailator / ImageIO → replace JPEG
    Rewrite content streams; remove metadata/orphans (partial)

Maven:
  pdfbox, thumbnailator, twelvemonkeys-imageio-*
System:
  ghostscript, qpdf

Presets map for UI:

12. SAMPLE OPENAPI SKETCH (contracts/pdf/openapi.yaml)
================================================================================

  openapi: 3.0.3
  info:
    title: EasyToolHub PDF API
    version: 0.1.0
  paths:
    /api/v1/pdf/health:
      get:
        summary: Liveness
        responses:
          "200":
            description: OK
    /api/v1/pdf/encrypt:
      post:
        summary: Password-protect a PDF
        requestBody:
          required: true
          content:
            multipart/form-data:
              schema:
                type: object
                required: [file, userPassword]
                properties:
                  file: { type: string, format: binary }
                  userPassword: { type: string }
                  ownerPassword: { type: string }
                  allowPrint: { type: boolean, default: true }
                  allowModify: { type: boolean, default: false }
        responses:
          "200":
            description: Encrypted PDF
            content:
              application/pdf:
                schema: { type: string, format: binary }
    /api/v1/pdf/decrypt:
      post:
        summary: Remove password from PDF
        requestBody:
          required: true
          content:
            multipart/form-data:
              schema:
                type: object
                required: [file, password]
                properties:
                  file: { type: string, format: binary }
                  password: { type: string }
        responses:
          "200":
            description: Decrypted PDF
            content:
              application/pdf:
                schema: { type: string, format: binary }
    /api/v1/pdf/compress:
      post:
        summary: Compress PDF (Ghostscript presets)
        requestBody:
          required: true
          content:
            multipart/form-data:
              schema:
                type: object
                required: [file]
                properties:
                  file: { type: string, format: binary }
                  quality: { type: string, enum: [low, medium, high] }

14. SAMPLE JAVA CLI WRAPPER NOTES (engine/QpdfEngine.java)
================================================================================

  Responsibilities:
    - Resolve QPDF_BIN from env (default "qpdf")
    - Write upload to /tmp/pdf-jobs/{uuid}/in.pdf
    - Run: qpdf --encrypt USER OWNER 256 -- in.pdf out.pdf

    - Read out.pdf bytes → return to controller
    - Delete directory in finally

  Similar:
    GhostscriptEngine.compress(in, out, preset)
